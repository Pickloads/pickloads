changed: no business logic, FMCSA rule, risk engine, Stripe flow, onboarding

## 0. A correction to M-99 and M-100

Both docs claimed `.mono` was applied ~97 times and **defined nowhere**, and a
test pinned that as a known gap.

**It was wrong.** `.mono` is defined at `src/app/v4.css:29`, converted
faithfully from the V4 prototype's own line 22. The M-99 search covered
`globals.css` and `portal.css` and never looked at `v4.css`, which is where the
V4 conversion lives.

Nothing was broken by it — no usage was removed and no rule was changed on the
strength of the claim. The test asserting the false premise has been deleted
and both docs corrected. §18 asked for `.mono` to be investigated rather than
blindly deleted; investigating it is what found the error.

## 1. Typography (§3)

M-100's scale was set from the brief's stated minimums and read too small on a
1440+ monitor. The fix is not a uniform increase — that shifts everything at
once and preserves the flatness. Secondary text moves to a comfortable floor;
the things a reviewer actually scans for move **further**, so the gap between
primary and secondary widens.

| Role | M-100 | M-100.1 | ≥1600px |
| --- | --- | --- | --- |
| Page title | 1.65rem | **1.75rem** | 1.875rem |
| Card title | 1.0625rem | **1.125rem** | — |
| Metric value | 1.7rem (hardcoded) | **1.9rem** token | — |
| Identifier (USDOT/MC/digest) | .85rem (hardcoded) | **.9375rem** token, 600 | .975rem |
| Body / value | .9rem | **.9375rem** | .975rem |
| Header metadata | — | **.8125rem** (new) | — |
| Label | .72rem | **.75rem** | — |
| Helper | .79rem | **.8125rem** | .84rem |
| Code | .72rem | **.75rem** | — |

Large monitors get one deliberate, bounded step at 1600px — plus a wider label
column (220px) and taller rows (56px) — rather than a fluid scale that would
drift into consumer-sized UI.

Two 10–11px leftovers the screenshots exposed: `.ptable td .tsub` (10px) and
`.ppager .pcount` (11px), both now on the 12px code scale, scoped to `.a-page`
so the customer portals keep their own.

## 2. Fewer boxes (§6, §9, §11)

The brief's "not tables inside boxes inside more boxes" was accurate.

- **Group bands** (IDENTITY / AUTHORITY / MATCHING / SOURCE) were filled bands
  with a rule above *and* below — objects in their own right. Now: no fill, no
  bottom rule, one hairline above, separation carried by space and the amber
  label. §9 asked for exactly this.
- **InfoCallout** was a full 1px box inside a 1px card. Now an accent rule down
  the left edge and a faint wash — no frame.
- **ReviewNote** was styled with the same sunken fill and 1px border as the
  editable textarea two cards away, which §11 calls out directly. Now a quoted
  record: faint wash, edge rule, no input chrome, 80ch measure.

## 3. Layout and large screens (§4)

Max content width 1720 → **1600px**, so rows stop becoming long horizontal
stretches. Row minimum 50 → 52px (56 at ≥1600). Badge metrics unified at 24px
min-height / 12px / 3px×12px padding, for both `.a-badge` and the mapped
`.pbadge`.

## 4. Defects only the screenshots found

None of these were visible to jsdom or to any structural assertion.

1. **Mapped card headings stopped short of the card edge.** `.a-page .pcard h2`
   drew its rule across the padding box while `.a-card-head` spans the full
   card — two card treatments in one system. Fixed with a full-bleed negative
   margin.
2. **The nine-stage pipeline funnel wrapped 7 + 2**, leaving an orphan row at
   1440. Minimum track 132 → 104px.
3. **"APPOINTMENT" then broke mid-word** in the narrower tile. Tighter side
   padding and tracking on compact tiles only; the label is still 11px+.
4. **The dashboard's per-dispatcher table had no scroll container at all**, so
   at 320px it pushed its card 8px past the viewport.
5. **Three dashboard scrollers had no keyboard route.** The insurance-expiring
   and unsigned-agreement tables contain only text and badges — no focusable
   element — so a keyboard user could not scroll them at all (axe
   `scrollable-region-focusable`, serious, WCAG 2.1.1). `ScrollRegion` already
   existed for exactly this and its own comment says to apply it uniformly; the
   admin pages had never adopted it. Now applied to the dashboard's four and
   the queue's two.

## 5. Coverage for the 19 mapped pages

M-100 left the mapped pages with no visual coverage: they are async Server
Components behind `requireStaff`, so neither jsdom nor the secretless e2e lane
can reach them, and §19 asks for dashboard screenshots.

`tests/unit/admin-mapped-vocabulary.test.tsx` renders a **specimen** of the
vocabulary those pages use — `.pbar`, `.psec`, `.ptiles`/`.ptile`, `.pcard`,
`.ptable-wrap`/`.ptable`, `.pbadge`, `.pempty`, `.timeline`, `.ppager`,
`.pgrid2` — in the arrangement the real pages use. It is emitted as a fixture,
photographed at four widths, measured at twelve, and axe-scanned.

**What it proves:** what the stylesheet does to that vocabulary.
**What it does not prove:** that the live dashboard uses exactly this
vocabulary in this order. Defects 1–3 above were found through it, and 4–5
were then confirmed in the real page source and fixed there — so it earned its
place, but it is not a substitute for opening the live routes.

## 8. Sign-off pass

### 8.1 `.ptable-wrap` keyboard debt — closed

Every scroll container in the admin portal now uses `ScrollRegion`
(`tabIndex` + `role="region"` + a label naming the stop).

| | Count |
| --- | --- |
| Admin scroll containers audited | 15 |
| Already converted (dashboard 4, queue 2, shipments/new 1) | 7 |
| Converted in this pass | 8 |
| Plain `.ptable-wrap` left in admin | **0** |
| Left unchanged, out of scope | 8 |

All 8 converted contain a real `<table className="ptable">` in at least one
branch, so each is genuinely scrollable when populated. Labels name the section
the table sits under rather than being generic.

The 8 left alone are carrier/shipper only — `carrier/invoices`,
`carrier/loads`, `carrier/profile`, `shipper/quotes`, plus `CarrierDocs`,
`FleetManager` (×2) and `SupportViews`. Import graphs confirm none is reachable
from an admin route, and §1 forbids touching those portals.

### 8.2 Consistency audit findings

Auditing the design-system block for lengths that bypass the tokens found one
real inconsistency and four drift risks:

- **The same identifier rendered at two sizes.** `.ptable td .tid` (the queue's
  USDOT) was `.85rem` while `dd.is-id` (the detail page's) was `.9375rem`. Both
  now use `--a-t-id`.
- Badge height, metric-grid minimums and the compact metric size were literals
  written **twice** each — once for the primitives, once for the mapped pages.
  That is how one design system becomes two. All now tokens
  (`--a-badge-h`, `--a-metric-min`, `--a-metric-min-sm`, `--a-t-metric-sm`).

### 8.3 A defect the fix itself caused

Unifying the identifier size widened the queue's USDOT column, and
`table-layout:auto` took the space from the applicant column — which
`overflow-wrap:anywhere` let shrink to its 170px floor, breaking the company
name over five lines and the email mid-word. Widening the floor then pushed
the seven-column table 54px past the card and **clipped the Review action**.

Measured rather than guessed: the widest column was FMCSA at 214px, set
entirely by `white-space:nowrap` on the badge `FMCSA UNAVAILABLE`. Badges
inside a table cell may now wrap — at word boundaries only
(`word-break:keep-all`), because the first attempt wrapped mid-word and read
worse than the clipping. Deficit went 54px → 0. Detail-page badges are
unaffected: the rule is scoped to `td`.

Interior table cells also moved from 24px to 16px horizontal padding, keeping
the card gutter on the first and last cell only. A seven-column table was
spending 336px on padding alone.
