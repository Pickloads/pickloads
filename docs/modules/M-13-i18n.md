# M-13 — Internationalization (next-intl, 5 locales)

**Status:** 🟡 Core complete; string migration ~70% (M-13b finishes interior pages) · **Phase:** 1 · **Date:** 2026-08-04

## What was built
- **Dictionary extraction pipeline** (`scripts/extract-i18n.mjs`): parses the vendored prototype (`reference/pickloadssitev4.html`) T/RICH dictionaries → `messages/{en,es,fr,ru,ht}.json`. 334 strings × 5 locales, keys = deterministic slugs of the English source (U-08: V4 dictionary stays the single source of truth). Rich HTML strings converted to next-intl tag syntax; entities normalized. Re-runnable any time the reference file changes.
- **Routing** (`src/i18n/routing.ts`): en default at `/`, others at `/es/...` etc. (`localePrefix: "as-needed"`, arch §2). `generateStaticParams` — all pages × 5 locales prerender statically (59 pages).
- **Middleware composition**: Supabase session refresh + portal protection runs first; next-intl locale handling second, with refreshed auth cookies carried over.
- **`useV4()` bridge** (`src/i18n/v4.ts`): components pass the English literal; the hook slugs it and returns the translation, falling back to English when a string was never in the V4 dictionary — missing entries degrade gracefully, never render raw keys.
- **Locale switcher**: the V4 `langsel` now genuinely switches locale, preserving the current path.
- `[locale]` layout sets `html lang`; catch-all route 404s unknown paths per locale.
